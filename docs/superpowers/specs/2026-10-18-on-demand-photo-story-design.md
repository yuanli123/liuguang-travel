## 1. 背景与目标

**问题**（需求方提出的两个痛点，同一根因——内容供给产能模型）：

1. 存量故事有限（12 篇散在 8 城），每次都需要手动维护故事生成；
2. 景点覆盖不够，用户游览的景点查不到故事，搜索是死胡同（「未找到匹配结果」toast）。

**解法方向**：用户搜不到/库里没有故事时，**拍照 + 定位识别景点，联网搜索相关信息，现场生成故事讲解**——内容供给从「预先生产」转向「按需生成」，无需逐篇人工维护。

**已确认的决策**（与需求方逐项确认）：

| 决策点 | 结论 |
|---|---|
| 入口 | 地图页常驻「📷 拍景点听故事」悬浮按钮 + 搜索无结果时兜底卡片 |
| 内容沉淀 | **一次性播放不沉淀**——不写 stories 库、无草稿队列、无审核流程（`ai_tasks` 成本留痕除外） |
| 技术栈 | 高德周边 POI（已有 key）+ 百度地标识别（免费额度）+ 视觉大模型兜底（GLM-4V-Flash 免费档 / Qwen-VL 可切换）+ 博查联网搜索（≈0.04 元/次）+ 复用 DeepSeek 写稿与 edge-tts 配音流水线 |
| 等待体验 | **先速览后故事**：博查 AI Search 现成信息先出文字速览（秒级），完整故事+配音后台继续，完成后自动切换 |
| 讲述模式 | 只生成默认「日常聊天」模式，播放页隐藏变体切换行（为速度换多模式） |
| 短缓存 | 同一天内同一景点走**内存级短缓存**（不落库）避免重复生成费用；如不需要可去掉（实现为一个 Map，重启即失效） |
| 合规 | 速览与播放页均标注「AI 生成 · 未经核查，仅供参考」；外部 key 全部服务端代理，不暴露前端 |

**硬约束**：一次完整生成（识别→搜索→写稿→配音）约 30-60 秒，等待体验由「先速览」解决；速览信息来自博查 AI Search 的结构化摘要，不额外配音。

## 2. 架构与数据流

新增后端路由 `server/src/routes/on-demand.js`（**无需登录**，参考 `ai.js` 的容错范式）。一条流水线：

```
输入：照片(可选) + 经纬度(必需) + 景点名(可选)
  ① 候选 POI：高德周边搜索（Web 服务 API，复用现有 AMap key）
     → 返回 5 个候选（名称/类型/距离），供识别与兜底选择
  ② 照片识别（有照片时）：
     a. 百度地标识别 API（免费额度）→ 命中著名景点直接确认；
     b. 未命中/未配置 → 视觉大模型兜底：输入照片 + 候选 POI + 定位，
        识别牌匾文字/建筑特征，返回景点名 + 置信度；
     c. 仍低置信 → 前端展示候选 POI 点选列表 + 手动输入名称
  ③ 速览（快路径，秒级）：博查 AI Search（query = 景点名 + 城市）
     → 摘要 + 来源链接，随响应立即返回前端展示
  ④ 故事（慢路径，后台继续）：博查 Web Search 取 2-4 条素材原文
     → DeepSeek 按现有 SYSTEM_PROMPT 写稿（仅 chat 模式，不生成变体）
     → edge-tts 配音（chat 模式音色，复用 modes.js）
     → 完成后前端自动切换播放
  ⑤ 不沉淀：内容只在响应/内存中传递，不写 stories 库；
     写一条 ai_tasks 留痕（type='on-demand'，记录识别/搜索/生成/配音成败与耗时）
```

### 2.1 接口设计

```
POST /api/on-demand/recognize
  入参: { image?: base64(jpg,≤4M), lat: number, lng: number, name?: string }
  响应(立即): {
    ok: true,
    jobId: string,            // 内存任务句柄
    spot: { name, city, source },     // 识别结果：photo|poi|user
    candidates?: [{name, distanceM}], // 低置信时返回，供前端点选
    fast: { summary, sources: [{title, url}], disclaimer } // 速览（可能为 null）
  }

GET /api/on-demand/:jobId    // 前端每 2s 轮询
  响应: { stage: 'searching'|'writing'|'voicing'|'done'|'failed',
          story?: { title, hook, script, sourceNote },
          audioUrl?: string, error?: string }
```

- 照片识别与速览是两段并行能力：识别完成后**立即**返回速览，写稿配音在后台进行——所以接口上拆成「立即响应 + 轮询补成品」，与「先速览后故事」的体验一致。
- 无照片但有名称（搜索兜底入口输入）→ 跳过 ① ②，直接用名称走 ③ ④。
- 短缓存：`Map<spotKey, jobId>`，key = 城市+景点名，同一天内命中直接返回缓存任务结果，不重复调用外部 API；进程重启失效。

## 3. 前端交互

改动集中在 `app.js` + `index.html` + `styles.css`。

### 3.1 入口

- **地图常驻**：地图页（`#view-map`）右下角悬浮圆钮「📷」（位于 `#mapStoryCard` 上方、`#mapStage` 右下），点击打开拍摄面板；
- **搜索兜底**：地图搜索与 Feed 搜索无结果时，空态由 toast 改为卡片：「没有现成故事 · 📷 拍一拍这个景点，或输入名称现场生成」→ 复用同一拍摄面板。

### 3.2 拍摄面板（新 overlay）

- H5 阶段：`<input type="file" accept="image/*" capture="environment">` 调起相机 + 相册选择；面板内提供「跳过拍照，直接输入景点名」文本框（不强制拍照）；
- Capacitor 阶段（roadmap 第 2-3 周）换原生 Camera 插件，接口不变；
- 定位：复用现有 `requestUserLocation()`（高德定位 + 原生兜底，C1 已实现），无定位时提示手动输入名称。

### 3.3 过程态

1. 拍照/输名提交后，面板显示步骤条：`识别中 → 搜集资料 → 创作中 → 配音中`（由轮询 stage 驱动）；
2. **速览先到**：步骤条下方先显示速览文字卡（摘要 + 来源链接 + 「AI 生成 · 未经核查」标注）；
3. **识别失败兜底**：识别低置信时展示候选 POI 点选列表（高德返回前 5 个）+ 手动输入框，用户点选/输入后重走流水线；
4. **成品到达**：音频合成完成后自动打开播放器（`openPlayer` 的 on-demand 分支）：
   - 播放页隐藏「讲述模式」切换行（单模式）；
   - 标题区/播放页加「未核查」角标；
   - 故事卡片不可收藏、不可加入行程（不沉淀，无 id）。

## 4. 合规与质量

- **标注**：速览卡与播放页均标注「AI 生成 · 未经核查，仅供参考」；速览展示来源链接（博查返回的 title+url）；
- **信源**：故事沿用现有 `sourceNote` 机制（「AI 生成，未经事实核查；基于联网搜索素材创作」）；
- **不沉淀**：不写 stories 库、无草稿、无上架流程；`ai_tasks` 留痕仅记录成败与耗时（不含照片，照片用后即弃，不落盘）；
- **key 安全**：百度地标/视觉模型/博查/高德 Web 服务 key 全部存 `server/.env`，走服务端代理；前端只传照片与坐标；
- 与 roadmap §5.3 质量红线的关系：本功能**不产生库存**，未核查内容仅向发起请求的用户本人播放且醒目标注，不触碰「批量上架」红线。

## 5. 错误处理与降级

| 故障 | 降级 |
|---|---|
| 无定位 | 提示手动输入景点名 |
| 百度地标/视觉模型未配置或失败 | 跳过照片识别，用 POI 名称兜底 |
| 博查未配置或失败 | 速览为 null，DeepSeek 按名称直接写（sourceNote 标注「素材有限」） |
| DeepSeek 写稿失败 | 速览仍在，轮询返回 failed + 提示稍后重试 |
| edge-tts 配音失败 | 返回无音频的成品，前端以文字稿展示（不阻塞） |
| 每步超时 | 复用 `geo.js` 的 `AbortSignal.timeout` 范式（单步 15-30s），全链 90s 上限后标记 failed |
| jobId 失效（服务重启） | 轮询 404 → 前端提示「生成任务已失效，请重新拍摄」 |

## 7. 成本与测试

### 7.1 成本估算（单次成功生成）

| 环节 | 单价 | 说明 |
|---|---|---|
| 百度地标识别 | 免费额度内 0 | 实名认证送几千次 |
| 视觉大模型 | 0（GLM-4V-Flash 免费档） | 仅地标未命中时调用 |
| 博查 AI Search + Web Search | ≈0.1 元 | 速览 + 素材各一次 |
| DeepSeek 写稿 | ≈0.01 元 | 350-550 字 |
| edge-tts | 0 | 本地合成 |
| **合计** | **≈0.11-0.15 元** | 短缓存命中时博查可省一次 |

### 7.2 测试清单

- 著名景点拍照全流程（地标识别命中）：速览秒级到达 → 故事+音频 → 自动播放；
- 长尾景点：地标未命中 → 视觉模型兜底 → 命中；兜底仍失败 → POI 点选列表 → 手动输入；
- 无定位、无照片仅名称、各 key 未配置的降级路径（§5 逐条）；
- 短缓存：同景点二次请求命中缓存，不再调用外部 API；
- 失败路径：博查失败（速览为 null 但故事仍生成）、DeepSeek 失败（failed + 提示）、全链超时；
- 成本留痕：`ai_tasks` 中 on-demand 记录可查。

## 8. 不做的事（YAGNI）

- 不做草稿库/审核队列/上架流程（一次性播放，与决策一致）；
- 不做 SSE 流式推送（轮询 2s 足够，留作后续优化）；
- 不做 4 模式变体生成（只 chat 模式）；
- 不做速览配音；
- 不做照片持久化（用后即弃）。
