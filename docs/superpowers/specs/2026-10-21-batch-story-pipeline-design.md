## 1. 背景与目标

**问题回顾**（需求方提出的痛点）：

1. 存量故事有限（12 篇散在 8 城），每次都需要手动维护故事生成；
2. 景点覆盖不够，用户游览的景点查不到故事。

**需求核心：提高 AI 生成景点的真实、准确性。** 需求方没有专业景点知识，无法人工核查事实——因此质量保障不能依赖人，必须建在生成流程里。

**已确认的决策**（与需求方逐项确认）：

| 决策点 | 结论 |
|---|---|
| 选题来源 | 高德按城市拉取 POI 清单 + 按需生成（拍景点）搜索留痕统计，两者都做，可多选 |
| 执行形态 | 管理面板批量任务（stats.html），非 CLI |
| 上架策略 | **自动上架 + 纠错下架**——不设人工审核门槛（需求方无专业审核能力，人工审核无意义） |
| 上架补全 | 批量只写 chat 主脚本；变体/配音/封面由流水线自动补齐后直接上架 |
| 质量保障 | 三层：①信源约束式生成 ②AI 事实核查 pass ③用户纠错 + 一键下架 |
| 合规 | 上架故事一律标注「AI 生成，未经事实核查」+ 信源说明；法规要求的是标注，本方案满足 |

**关键原则（真实准确优先）**：搜不到可靠素材的景点**宁可不生成**（标记失败，面板可见），也不让 AI 凭空编造。

## 2. 整体流水线

```
选题清单（§4）
  → 面板勾选（每批 ≤20）
  → 后台队列（并发 2）逐篇：
      ① 博查 Web Search 搜素材（搜不到 → 该篇 failed，跳过）
      ② DeepSeek 约束写稿（只依据素材，不确定处模糊表述）
      ③ DeepSeek 事实核查 pass（对照素材删改无据内容 → 修正稿）
      ④ 风格转换 3 个讲述模式变体（transferModes）
      ⑤ 4 模式 edge-tts 配音 + SVG 封面
      ⑥ 上架（status=2），App 立即可听
  → 面板 2s 轮询进度；失败篇可勾选重试
```

与按需生成（拍景点）共用素材与核查能力：`runNarrate` 同样接入第 ②③ 步（本次一并升级）。

## 3. 质量保障三层

### 3.1 信源约束式生成

新增共享提示词常量（`lib/ai-generate.js`）：写稿用户提示词强制约束——

> 你只能依据下方「参考素材」创作，素材中没有的事实一律不得出现；
> 无法确定的信息用「据说」「相传」「有一种说法」等模糊表述；
> 不写具体年份数字（除非素材明确给出）；不评价、不拔高。

素材由 `bochaWebSearch(景点名 + 城市)` 提供（复用 `lib/websearch.js`）。素材为空（无 key / 搜索失败 / 无结果）→ **该篇不生成，标记 failed**，面板显示原因。

### 3.2 AI 事实核查 pass（新增 `lib/fact-check.js`）

```js
factCheckStory(material, script) → { script, issues }
```

第二次 DeepSeek 调用扮演核查员：对照素材逐条检查草稿的事实主张，**删除素材不支撑的内容、把具体数字/年代改为模糊表述**，输出修正稿与问题清单（issues 仅留痕，不阻塞）。核查调用失败 → 保留原稿（原稿已受 3.1 约束，风险可控），sourceNote 不变。

### 3.3 用户纠错 + 一键下架（事后闭环）

- 现有纠错系统保持（用户报 → 管理端处理），播放页信源说明含「AI 生成，未经事实核查」；
- **新增一键下架**：`POST /api/admin/ai/:id/unpublish`（status 2 → 0 草稿），App 立即不可见；
- 前端故事卡片显示「AI 生成·未核查」角标（sourceNote 以「AI 生成」开头的故事）。

## 4. 选题清单

`POST /api/admin/ai/batch-plan` 入参 `{ source: "amap-city" | "on-demand", city?, limit? }`：

- **amap-city**：高德 POI 文本搜索（城市 + 风景名胜类，`lib/amap.js` 新增 `amapCityAttractions(city)`，分类码实现时按高德文档核对）；
- **on-demand**：聚合 `ai_tasks` 中 `type='on-demand' AND status='done'` 的 `input_material.spot.name` + 城市频次，取 Top N（用户真实搜过/拍过但没听上的）；
- **统一去重**：同名同城已在 stories 表（含草稿）的自动排除；同批任务内去重。

## 5. 批量任务机制

- 任务内存态（与按需生成一致）：`Map<jobId, { topics, done, failed, results, startedAt }>`，TTL 30 分钟；
- 并发 2（DeepSeek 限速友好），单篇各步超时沿用现有 `AbortSignal.timeout` 范式；
- 每篇留痕 `ai_tasks`（type 扩展 `batch`，input 含景点名/城市，result 含 storyId 或失败原因）；
- 失败篇可勾选重试（复用同一生成接口，1 篇也是一批）。

## 6. 接口设计（均需 ADMIN_TOKEN）

| 接口 | 用途 |
|---|---|
| `POST /api/admin/ai/batch-plan` | 选题清单（两来源，去重后返回可勾选列表） |
| `POST /api/admin/ai/batch-generate` | `{ topics: [{name, city}] }` 提交批量任务 → `{ jobId }` |
| `GET /api/admin/ai/batch/:jobId` | `{ done, failed, total, results:[{name, ok, storyId?, error?}] }` |
| `POST /api/admin/ai/:id/unpublish` | 一键下架（status → 0） |

批量生成复用 `ai.js` 现有 `/stories` 的落库逻辑（slug 查重、story_variants、story_topics、自动封面、城市点位），上架即 status=2。

## 9. 成本与测试

### 9.1 成本（单篇全流程）

| 环节 | 单价 | 次数 |
|---|---|---|
| 博查 Web Search | 0.036 元 | 1 |
| DeepSeek 写稿 + 核查 + 3 变体 | ≈0.01 元 | 5 |
| edge-tts 4 模式配音 / SVG 封面 | 免费 | — |
| **合计** | **≈0.09 元/篇** | 20 篇 ≈ 1.8 元 |

### 9.2 测试清单

- batch-plan 两来源与去重（同名同城不出现）；
- 小批量（2 篇）真实跑通：素材 → 约束写稿 → 核查修正 → 变体 → 配音 → 上架，App 可见；
- 素材搜不到 → 该篇 failed 且原因可见，其余正常完成；
- 核查 pass 修正效果抽查（人工读一篇对比）；
- unpublish 后 App 列表/详情不可见；
- 角标只出现在 AI 生成故事上，手写稿不出现；
- 按需生成（拍景点）升级后回归：素材约束 + 核查 pass 生效。

## 10. 不做的事（YAGNI）

- 不做草稿审核/编辑界面（自动上架策略下无草稿环节）；
- 不做定时批量任务（手动触发即可）；
- 不做素材库/知识库建设（直接搜，不加缓存层）；
- 不做多模型交叉核查（单模型核查 pass 先行，留痕数据积累后再评估）。
